Method A — MSIX install (no Developer Mode needed)

The MSIX is signed with a self-signed certificate (CN=AccessOS). You must trust this certificate once before installing. The certificate is only for local testing — it is not a public CA.

Step 1 — Trust the certificate (one-time)

1
Open an elevated PowerShell (Run as Administrator)

Press Win + X → Windows PowerShell (Admin) or Terminal (Admin).

2
Import the certificate into Trusted Root
Import-PfxCertificate `
  -FilePath "C:\Users\PrasannaNariboina\OneDrive - IBM\Prasan_Devops\AccessOS\installer\AccessOSDev.pfx" `
  -CertStoreLocation "Cert:\LocalMachine\Root" `
  -Password (ConvertTo-SecureString "AccessOSDev123!" -AsPlainText -Force)

You should see the certificate details printed. This trusts the cert system-wide for this machine only.

Step 2 — Install the MSIX

3
Double-click the MSIX file

Navigate to: C:\Users\PrasannaNariboina\OneDrive - IBM\Prasan_Devops\AccessOS\dist\AccessOS-Debug-x64.msix

Double-click it. Windows shows the App Installer dialog.

4
Click Install

The installer shows AccessOS with version 0.1.0.0. Click Install.

If the Install button is greyed out, the certificate was not trusted — re-do Step 2.

5
Launch AccessOS

After installation: press Win, type AccessOS, press Enter.

Or install via PowerShell (no double-click needed):

Add-AppxPackage "C:\Users\PrasannaNariboina\OneDrive - IBM\Prasan_Devops\AccessOS\dist\AccessOS-Debug-x64.msix"

Method B — Developer Mode (winapp run)

Developer Mode must be enabled. If you see "Developer Mode is not enabled", follow Step 1 below.
1
Enable Developer Mode in Windows Settings

Press Win + I → Privacy & security → For developers → toggle Developer Mode to On. Confirm the UAC prompt.

Alternatively, run this in an elevated PowerShell:

$p = "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\AppModelUnlock"
Set-ItemProperty $p AllowDevelopmentWithoutDevLicense 1 -Type DWord
Set-ItemProperty $p AllowAllTrustedApps 1 -Type DWord
2
Run via winapp (from repository root)
$winapp = "$env:USERPROFILE\.nuget\packages\microsoft.windows.sdk.buildtools.winapp\0.6.1\tools\win-x64\winapp.exe"
& $winapp run ".\src\UI\AccessOS.UI.csproj" -c Debug --arch x64

This builds, registers a package identity, and launches the app in one step. The window opens automatically.

Uninstalling

# Remove the MSIX package
Get-AppxPackage -Name "AccessOS.ScreenReader" | Remove-AppxPackage

# Remove the dev certificate (optional cleanup)
Get-ChildItem Cert:\LocalMachine\Root | Where-Object Subject -eq "CN=AccessOS" | Remove-Item

Troubleshooting

ProblemFix
"Install" button greyed out in App Installer The certificate is not trusted. Re-run Step 1 in an elevated PowerShell (Run as Administrator).
No speech after clicking Start Check Settings → Time & Language → Speech — at least one SAPI voice must be installed. Try Microsoft David or Zira.
COMException 0x80040154 on launch Package identity not registered. Use Method A (MSIX install) or Method B (winapp run).
AccessOSCore_d.dll not found Run cmake --build build --target AccessOSCoreDll --config Debug first. The DLL post-build copies it automatically.
App Installer not available Install it from the Microsoft Store, or use PowerShell: Add-AppxPackage ".\dist\AccessOS-Debug-x64.msix"
winapp: "Developer Mode is not enabled" Enable Developer Mode via Settings → Privacy & security → For developers.
